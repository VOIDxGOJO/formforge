# FormForge 2.0: report, presentation and research

Everything behind the FormForge 2.0 dissertation (PMCA699J, MCA, VIT): the documents, the experiments that produce every number in them, and the scripts that rebuild them.

## Documents

| File | What it is |
|------|------------|
| [FormForge_Report.pdf](FormForge_Report.pdf) / [.docx](FormForge_Report.docx) | Full project report (VIT template, 90 pages) |
| [FormForge_Project_Overview.pdf](FormForge_Project_Overview.pdf) / [.docx](FormForge_Project_Overview.docx) | Plain-language overview: problem, audience, every function, novelty, flows with flowcharts |
| [deck/FormForge_Review_Presentation.pptx](deck/FormForge_Review_Presentation.pptx) | 25-slide review presentation ([PDF preview](deck/deck_preview.pdf)) |

## Folders

| Folder | Contents |
|--------|----------|
| `experiments/` | Python research code: adaptive engine simulation (`adaptive_sim.py`), ablation, stopping-rule sensitivity, quality analyzer and PII evaluation, plus `results/*.json` and the run logs |
| `figures/` | Diagrams and charts used in the report and deck (generated by `experiments/diagrams.py`, `diagrams2.py`, `charts.py`) |
| `screens/` | Screenshots of the running app (s01-s15) |
| `build/` | Generator for the report (`node build/build.js`, then `build/word_finalize.ps1` in Word) |
| `deck/` | Generator for the presentation (`build_deck.js`, `render_ppt.ps1`) |
| `explainer/` | Generator and flowcharts for the overview document |
| `e2e_*.mjs`, `e2e_adaptive_data.json`, `seed.sql` | Demo data and end-to-end scripts that create the demo forms against a running API |

## Reproducing the numbers

```bash
cd report/experiments
python adaptive_sim.py 5     # static vs rule-based vs adaptive (5 seeds) + cold start
python ablation.py 3         # utility term ablation
python sensitivity.py        # stopping rule sensitivity
python quality_eval.py       # quality analyzer + PII redactor on the labelled sets
python charts.py             # chapter 7 charts
```

## Demo accounts

The demo accounts are created by **`npm run db:seed`** in the repository root, after `npm run db:migrate`. It builds the whole demo workspace used in the report and the screenshots: seven forms, 600+ responses over the last 30 days, a trained adaptive model, a warm-started form and cached insights. The logins (`demo.reviewer@formforge.test` as Owner, `invitee@formforge.test` as Viewer) and their passwords are in [`apps/api/prisma/demo/accounts.json`](../apps/api/prisma/demo/accounts.json) and in `demo_seed_credentials.txt`. They exist only in your own database and give no access to anything online. The AI key is never stored here; put your own key in `apps/api/.env` (see the main README).

`seed.sql` is an older export of raw responses only. It is kept for reference and does not create accounts; use `npm run db:seed` instead.

## Rebuilding the documents

```bash
cd report
npm install                  # docx, pptxgenjs, sharp, react-icons
node build/build.js          # writes FormForge_Report_raw.docx; open in Word or run word_finalize.ps1
node explainer/build_explainer.js
```

The deck build also needs the `apply_theme.js` helper from the pptx skill (`PPTX_SKILL` environment variable) and `NODE_PATH` pointing at `report/node_modules`.
